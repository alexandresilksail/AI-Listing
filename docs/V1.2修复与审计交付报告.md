## 二、每项问题的修复前后说明

### P0-1 前端 API Token 泄露（最严重）

**修复前**：`docker-compose.yml` 把 `PL_API_TOKEN` 作为 build-arg `VITE_API_TOKEN` 传给前端构建 → `frontend/Dockerfile` 注入构建环境 → Vite 将 `import.meta.env.VITE_API_TOKEN` **内联进 dist/*.js**。任何访问网站的人从 JS bundle 即可提取生产令牌，调用全部管理 API。

**修复后**：
- compose 删除 build-args 传递；Dockerfile 删除 ARG/ENV；client.ts 删除 env 读取——三重清零
- 前端令牌仅运行时输入并存 localStorage（401 引导弹窗）
- 测试强制：compose/Dockerfile/client.ts/dist 产物均不得出现注入痕迹（4 项测试）
- README 明确架构局限：单一共享 Token，未实现多用户隔离（不宣称）

### P0-2 文本模型适配器 json_mode

**修复前**：`registry` 传 `json_mode=` 但基类无此参数（靠子类 `*args` 绕过，任何新适配器直接崩）；`_chat()` 从全局配置读 `use_json_mode`，**实例的 json_mode 形同虚设**；截断/非法 JSON 错误信息含糊；401 也重试。

**修复后**：
- 基类/注册器/具体适配器签名统一（inspect 测试强制）
- `self.json_mode` 真正进入请求体（MockTransport 捕获验证：json_object 带 response_format / none 不带）
- 400 自动降级重试；429/5xx/网络异常重试；4xx 立即失败且脱敏
- 截断/非 JSON/缺核心字段 → 明确 ValueError，任务标记 failed，**绝不补空伪装成功**
- httpx.Timeout 分段（connect 10s / read timeout / write 30s / pool 10s）

### P1-3 任务超时与恢复

**修复前**：`wait_for(to_thread(...))` 超时后线程继续运行且无防护——旧执行可能覆盖重试任务；`db` Session 跨线程共享（SQLAlchemy 非线程安全）；httpx 无分段超时。

**修复后**：
- **epoch 任务版本号**：submit/retry/recover 均 +1；终态 `finalize()` 条件写入 `WHERE id=? AND epoch=?`；旧执行醒来发现 epoch 已变即丢弃（不调模型、不写库、不产生费用）
- `_mark_failed` 同样 epoch 防护（过期 job 不误标重试后任务）
- `_run_sync` 内创建/关闭独立 Session（消除跨线程共享）
- 重启恢复沿用 V1.1 对账（pending 重排队/processing 标 failed），且恢复提交也递增 epoch
- 已成功产物保留策略不变（单张失败不清空整批）

### P1-4 路径安全

**修复前**：`safe_join` 用 `str(target).startswith(str(base))`——`/data/images_evil/x.png` 因同前缀绕过。

**修复后**：`Path.relative_to()` 目录组件级校验 + `resolve()` 规范化（`..`/绝对路径/符号链接）；`is_within()` 辅助；storage.delete 拦截记日志。8 项测试覆盖全部攻击面。

### P1-5 图片 API 与 SSRF

**修复前**：V1.1 已有协议/内网/重定向/大小防护；缺内容类型校验、单张失败拖垮整批、无分段超时。

**修复后**：Content-Type 白名单（image/png|jpeg|webp）；单张下载/解码失败跳过并留痕、全部失败抛错（不造假成功记录）；b64 严格校验；分段超时；DNS 重绑定作为已知限制在代码注释与 README 如实说明（TOCTOU 窗口以逐跳校验+主机锁定缓解）。

### P1-6 成本与预算

**修复后**（V1.1 三态基础上增强）：
- `PRICING_VERSION` 价格表版本 + ApiCallLog `cost_basis`（estimated/actual/unknown）+ `price_version`，估算依据可追溯
- **原子预留**：`check_and_reserve` 持锁内比较 `spend + reserved + est > daily` 并计入预留；`release_reservation` 在任务 finally 成对释放——消除检查→执行窗口的并发超支（4 项测试）
- 未知费用不预留（无法预留），盲区由 `today_unknown_cost_calls` 单独计数提示
- 重试任务按新 epoch 重新检查预算；已发生的费用以 ApiCallLog 实际记录为准

### P1-7 Docker 与数据库迁移

**修复后**：
- Alembic 三版本：0001 baseline（create_all 幂等）→ 0002 cost_usd 可空（batch 重建，幂等）→ 0003 epoch/cost_basis/price_version（ADD COLUMN，幂等）
- 启动自动 `apply_migrations()`：**迁移前自动备份**（`<db>.bak-<时间戳>`）；失败回滚 + RuntimeError 阻止启动 + **绝不清库**
- **真实库实测**：现有 V1.1 库（9 行历史任务）启动即自动升级，新列就位、数据完整、备份文件生成
- 旧库升级测试：构造 V1.0 风格旧库（cost_usd NOT NULL）→ 迁移 → 新列 + NULL 可插入 + 数据保留
- 迁移失败测试：注入失败脚本 → 回滚 → 数据原样 → RuntimeError
- backend/Dockerfile 已含 migrations/ 与 alembic.ini（V1.1 已确认）

## 九、尚未解决的问题及其风险

1. **Docker 未经实机验证**——静态校验通过，首次部署需实测。
2. **真实 OpenAI 兼容 API 未联调**——mock 覆盖成功/超时/限流/服务端错误/非法响应路径，但无真实 Key 调用记录；接入后请先小批量验证并补价格表。
3. **DNS 重绑定残留窗口**——URL 校验与连接间 TOCTOU；以逐跳校验+主机锁定缓解；彻底防护需连接层绑定 IP（与 HTTPS 证书校验冲突），高风险部署走受控出网代理。
4. **超时后僵尸线程竞态**——wait_for 超时不杀同步线程；epoch + 幂等键保证不覆盖、不重复扣费，但线程资源释放依赖调用方超时。
5. **单一共享 Token，无多用户隔离**——任何持令牌方拥有全部权限；RBAC 需后续版本。
6. **未知费用盲区**——allow 策略下不预留不计入，仅计数提示；敏感场景用 block。
7. **batch 迁移依赖表结构兼容**——0002 的 batch 重建按现有列拷贝，若用户库有自定义列需人工核对（备份兜底）。
