## 一、审计发现的问题与修复对照

### 1. 生产安全（最高优先级）

| # | 问题（审计发现） | 修复 | 证据 |
|---|---|---|---|
| 1.1 | **所有 API 无鉴权**，管理接口裸奔 | 新增 `backend/app/auth.py` 全局依赖：`Authorization: Bearer` / `X-API-Token` 双方式，`hmac.compare_digest` 常量时间比较；仅 `/api/health`、`/api/meta` 公开 | 28 个端点无令牌 401 实测 + 33 项鉴权测试 |
| 1.2 | `PL_API_TOKEN` 为空时接口仍公开（原逻辑「无令牌即放行」） | **`PL_ENV=production` + 无令牌 → lifespan fail-fast 拒绝启动**；开发模式打印醒目警告 | 子进程实测：production 无令牌启动失败并退出 |
| 1.3 | 图片 URL 直取，可被打成 SSRF（内网探测/云元数据窃取） | 重写 `security.py`：`_BLOCKED_NETS` 黑名单（私网/环回/链路本地/169.254.169.254/IPv6 ULA/保留段）；`socket.getaddrinfo` 解析后逐 IP 校验；重定向逐跳校验 + 主机锁定；流式下载大小上限 | 18 项 SSRF 测试（含本地 mock 服务器对照） |
| 1.4 | 上传仅校验扩展名与大小，可被伪造格式/解压炸弹攻击 | 增加 **文件魔数校验 + PIL `Image.open().load()` 完整解码 + `MAX_IMAGE_PIXELS` 像素上限** | 6 项上传测试（假扩展名/损坏/超大/像素上限） |
| 1.5 | API Key 可能经错误响应/日志外泄 | 新增 `scrub_secrets()` 过滤所有错误信息与日志；`mask_secret()` 脱敏展示；`test_connection` 错误脱敏 | 3 项脱敏测试 + 设置接口测试 |

### 2. 后台任务可靠性

| # | 问题 | 修复 | 证据 |
|---|---|---|---|
| 2.1 | worker 异常被静默吞掉，队列假死 | `_run` 异常 `logger.exception` 全量留痕 + 标记任务 failed，队列继续存活 | test_worker_exception_is_recorded_and_queue_survives |
| 2.2 | 重启后 pending 任务丢失、processing 任务永卡「处理中」 | `recover_on_startup()`：pending 重新入队、processing 标记 failed | 2 项重启恢复测试 |
| 2.3 | 并发提交可重复扣费 | 提交路由 `threading.Lock` 串行化「查重+落库」 | 5 线程并发去重测试 |
| 2.4 | 任务无超时，网络悬挂永久占用 worker | `asyncio.wait_for` 单任务超时（`PL_TASK_TIMEOUT_SEC`，默认 300s） | test_task_timeout_marks_failed |
| 2.5 | 预算函数从未被调用（预算形同虚设） | 执行前真实调用 `check_budget()`：listing 按预估算、image 按张数；`threading.Lock` 持锁检查防并发穿透 | 3 项预算测试 |
| 2.6 | TestClient 多事件循环冲突（「Task attached to a different loop」） | 任务队列改为**独立后台线程 + 私有事件循环**，`call_soon_threadsafe` 跨线程安全入队 | 120 项测试全绿（含原失败场景回归） |

> **Redis + Celery 评估结论**：当前单 worker 线程 + 私有事件循环已满足中小规模场景（队列吞吐受 AI 调用速率限制，不在 worker 本身）。任务接口已按可替换设计（`TaskQueue.submit/retry`），规模化时可在不改业务层的前提下替换为 Celery + Redis。**V1.1 不引入**，避免过度工程。

## 五、未解决问题与已知限制（诚实清单）

1. **Docker 未经实机验证**——配置经静态校验（YAML/COPY 路径/healthcheck/卷/模板变量），首次部署请以 `docker compose up -d --build` 实测结果为准。
2. **真实 API 未联调**——`json_mode` 降级、按模型尺寸映射等兼容逻辑依赖测试保证；接入真实 Key 后请先小批量验证，并把实际模型价格补入 `PRICING`。
3. **SQLite 旧库升级需手动处理**——`init_db()` 不 ALTER 已存在的表；V1.0 升级见 Linux 部署指南「V1.0 → V1.1 升级特别说明」。
4. **任务超时后僵尸线程竞态**——`asyncio.wait_for` 超时后任务标记 failed、队列不阻塞、幂等键防重复扣费，但底层 HTTP 调用若仍悬挂，该线程资源释放依赖调用方超时（`PL_REQUEST_TIMEOUT_SEC`）。
5. **单 worker 上限**——内建队列为单 worker；高并发场景建议替换 Celery + Redis（接口已预留）。
6. **372 条 DeprecationWarning**——来自 SQLAlchemy 2.0 对 `datetime.utcnow` 等的弃用提示（业务代码已修，其余多在依赖内部），不影响运行。
